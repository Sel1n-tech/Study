
Команда **`git branch`** в Git используется для работы с ветками: создания, просмотра, переименования и удаления.

```bash
# вызов полной справки по команде (в браузере)
git branch --help

# вызов краткой справки по команде (в терминале)
git branch -h
```

## **Просмотр списка веток**

```bash
# Локальные ветки (текущая выделена `*`)
git branch       

# Все ветки (локальные + удалённые)
git branch -a    

# Показывает удалённые ветки
git branch -r                  

# Показывает последний коммит в каждой ветке
git branch -v    

# Показывает связь локальных и удалённых веток
git branch -vv                 
```

## Команда `git push` с ветками

```bash
# пушим текущую ветку
git push

# проверяем
git branch -r                  
git branch -vv     

# пушим все ветки в origin
git push --all origin            

# проверяем
git branch -r                  
git branch -vv     

# выборочный пуш указанных веток
git push origin branch1 branch2 branch3
```

**Как работает `git push --all origin`**

- Git отправляет **все ветки**, которые есть локально, но отсутствуют на **origin**.
- Если ветка уже существует на удалённом сервере, Git попытается обновить её (если нет конфликтов).
- **origin** - имя удалённого репозитория; указывает, куда отправлять ветки

## **Создание новой ветки**

git branch <имя_ветки>          # Создаёт ветку, но не переключается на нее
git branch <имя_ветки> <коммит> # Создаёт ветку от указанного коммита

```bash
# создать новую ветку (но остаться на текущей)
git branch some-new-branch

# проверить (вывести все локальные ветки)
git branch

# переключиться на указанную ветку
git switch some-new-branch

# проверить 
git branch

# переключиться назад на ветку master
git switch master
```

# Сценарий исправления бага в отдельной ветке

```bash
# выводим дерево коммитов
git log --oneline --graph

# переключаемся на разные коммиты в поисках появления бага
git checkout 812a063
ls
git checkout f0ac494
ls

# возвращаемся на ветку master
git checkout master

# создаем новую ветку (от указанного коммита) для исправления бага
git branch hotfix/fix-login-bug 7f39bc7

# переключаемся на новую ветку
git checkout hotfix/fix-login-bug

# убеждаемся в успешном перемещении
git log --oneline --graph
ls
ls web_pages/

# вносим требуемые исправления
nano web_pages/page3.html

# готовим новый коммит
git status
git add .
git status
git commit -m "fix page3 bug"

# проверяем появление коммита
git log --oneline --graph

# возвращаемся на ветку master для слияния
git switch master

# выполняем слияние (merge)
git merge hotfix/fix-login-bug

# проверяем результат
git log --oneline --graph
```

# Альтернативные команды

```bash
# создать новую ветку и переключиться на нее (заменяет следующие 2 команды)
git checkout -b <new_branch>

# только создать новую ветку
git branch <new_branch>

# только переключиться на новую ветку
git checkout <new_branch>

# создать новую ветку и переключиться на нее (заменяет предыдущие 2 команды)
git switch -c <new_branch>
```


## **Удаление веток**

git branch -d <имя_ветки>   # Безопасное удаление (только если изменения слиты)
git branch -D <имя_ветки>   # Принудительное удаление (даже если не слито)

**Пример:**

```bash
# удаление пустой или слитой ветки
git branch -d old-feature

# форсированное удаление ветки (даже если она не слита)
git branch -D old-feature

# проверка списка локальных веток
git branch
```

## **Переименование ветки**

git branch -m <старое_имя> <новое_имя>  # Переименовывает ветку
git branch -m <новое_имя>               # Переименовывает ТЕКУЩУЮ ветку

**Пример:**

```bash
# выводим список локальных веток
git branch

# переименовываем ветку master в main
git branch -m master main

# выводим список локальных веток
git branch

# переименовываем ветку main в master
git branch -m main master

# выводим список локальных веток
git branch
```

## **Поиск ветки по названию**

git branch --list  # Поиск веток с фильтрацией по имени

**Пример:**

```bash
# Находит все ветки со словом `feature` в названии
git branch --list '*feature*'
```

## **Разница между `git branch` и `git checkout -b`**

|Команда|Действие|
|---|---|
|`git branch new-feature`|Только создаёт ветку, но **не переключает**|
|`git checkout -b new-feature`|Создаёт **и сразу переключается**|
|`git switch -c <ветка>`|Создаёт **и сразу переключается** (в Git версии 2.23+)|

### ⚠️ **Осторожно!**

- Удаление ветки (`-D`) **необратимо** (если только коммит не сохранён в другой ветке).
    
- `git branch -m` не обновляет удалённые ветки — нужно пушить изменения
