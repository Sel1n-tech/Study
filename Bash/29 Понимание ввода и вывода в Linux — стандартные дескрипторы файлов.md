## Введение

Вы уже умеете перенаправлять вывод команд в файлы (`>` и `>>`) и передавать данные из одного файла в другой с помощью конвейера (`|`). Но что происходит «под капотом», когда вы пишете `echo "Hello" > output.txt` или запускаете `cat < input.txt`?

В Linux (и Unix-подобных системах) всё — файлы, включая **ввод и вывод**. Для управления ими используются специальные **дескрипторы файлов**, которые обозначаются числами: `0`, `1`, `2`.

Этот урок поможет вам:

- Понять, что такое стандартные дескрипторы файлов.
- Разобраться, как работают `STDIN`, `STDOUT` и `STDERR`.
- Научиться перенаправлять не только обычный вывод, но и ошибки.
- Создавать надёжные скрипты, которые корректно обрабатывают данные и ошибки.

## Стандартные дескрипторы файлов

В Linux каждому процессу доступны три стандартных потока ввода/вывода:

|Дескриптор|Аббревиатура|Описание|
|---|---|---|
|`0`|`STDIN`|Стандартный ввод (по умолчанию — клавиатура)|
|`1`|`STDOUT`|Стандартный вывод (по умолчанию — терминал)|
|`2`|`STDERR`|Стандартный вывод ошибок (по умолчанию — терминал)|

Эти дескрипторы всегда присутствуют в каждом процессе. Их можно перенаправить в файлы или другие устройства.

## Стандартный ввод (STDIN)

### Что это такое?

`STDIN` — это поток данных, который по умолчанию приходит с клавиатуры.

Многие команды (например, `cat`, `read`) читают данные именно из `STDIN`.

### Ввод с клавиатуры

Файл `input_from_keyboard.sh`:

```bash
#!/bin/bash
# Читаем ввод с клавиатуры

echo "Введите несколько строк (Ctrl+D для завершения):"
cat
```

Команда `cat` без аргументов читает данные из `STDIN` и выводит их на экран.

![](https://ucarecdn.stepik.net/041f7727-4ab0-4d6f-aad0-7e9b8790ff1c/)

### Перенаправление ввода из файла

Файл `input_from_file.sh`:

```bash
#!/bin/bash
# Читаем ввод из файла

echo "Содержимое файла:"
cat < data.txt
```

![](https://ucarecdn.stepik.net/f45a9e04-4505-46f6-8444-0a3aa1fae35f/)

Оператор `<` перенаправляет содержимое файла в `STDIN` команды `cat`.

## Стандартный вывод (STDOUT)

### Что это такое?

`STDOUT` — это поток данных, который по умолчанию выводится на экран. Большинство команд (например, `ls`, `echo`, `grep`) отправляют свой основной вывод именно в `STDOUT`.

### Перенаправление вывода в файл

Файл `output_to_file.sh`:

```bash
#!/bin/bash
# Перенаправляем вывод в файл

echo "Это сообщение будет в файле."
ls -l > output.txt
echo "Список файлов записан в output.txt"
```

![](https://ucarecdn.stepik.net/c3095fc4-7bd7-4486-93cb-8259ebb9cdac/)

Оператор `>` перенаправляет `STDOUT` команды `ls` в файл `output.txt`.

### Добавление вывода в файл

Файл `append_output.sh`:

```bash
#!/bin/bash
# Добавляем вывод в конец файла

echo "Начинаем логирование..."
date >> log.txt
echo "Текущее время записано в log.txt"
```

![](https://ucarecdn.stepik.net/fc50c5fd-19be-416c-bf13-cf767f522a55/)

Оператор `>>` добавляет вывод в конец файла, не стирая его содержимое.

## Стандартный вывод ошибок (STDERR)

### Что это такое?

`STDERR` — это поток данных, который используется для вывода **сообщений об ошибках**. По умолчанию он также выводится на экран, но его можно перенаправить отдельно от `STDOUT`.

### Перенаправление ошибок

Файл `redirect_errors.sh`:

```bash
#!/bin/bash
# Перенаправляем ошибки в файл

echo "Попробуем прочитать несуществующий файл:"
ls -l badfile.txt 2> errors.txt
echo "Ошибки записаны в errors.txt"
```

![](https://ucarecdn.stepik.net/59b927b0-ef5f-44f9-9b00-c91668b0f137/)

Оператор `2>` перенаправляет `STDERR` (дескриптор `2`) в файл `errors.txt`.

### Перенаправление и ошибок, и вывода

Файл `separate_output.sh`:

```bash
#!/bin/bash
# Разделяем нормальный вывод и ошибки

echo "Проверяем существование файлов:"
ls -l test.txt badfile.txt 1> output.txt 2> errors.txt
echo "Результаты записаны в output.txt и errors.txt"
```

![](https://ucarecdn.stepik.net/8cc84f90-de34-4039-ad28-34d03a68f323/)

`1>` — перенаправляет `STDOUT`, `2>` — перенаправляет `STDERR`.

### Объединение вывода и ошибок

Файл `combine_output.sh`:

```bash
#!/bin/bash
# Объединяем вывод и ошибки в один файл

echo "Объединяем вывод и ошибки:"
ls -l test.txt badfile.txt > combined.txt 2>&1
echo "Результаты записаны в combined.txt"
```

![](https://ucarecdn.stepik.net/389a4191-c1bb-4763-919b-58ece5432e17/)

`2>&1` означает: «перенаправить `STDERR` (2) туда же, куда направлен `STDOUT` (1)».

## Практическое задание: создайте скрипт «Анализ директории»

### Цель:

Написать скрипт `analyze_dir.sh`, который:

1. Принимает имя директории как параметр.
2. Проверяет, существует ли директория.
3. Если директория существует — выводит список файлов в ней.
4. Если директория не существует — выводит сообщение об ошибке в файл `errors.log`.
5. В конце выводит общее количество файлов и директорий.

### Инструкция:

1. Создайте файл `analyze_dir.sh`.
2. Добавьте shebang `#!/bin/bash`.
3. Проверьте количество аргументов: `if [ $# -ne 1 ]; then ... exit 1; fi`.
4. Проверьте существование директории: `if [ ! -d "$1" ]; then ... exit 1; fi`.
5. Используйте `ls -l` для получения списка файлов.
6. Сохраните вывод в файл `output.txt`, ошибки — в `errors.log`.
7. Сохраните, дайте права: `chmod u+x analyze_dir.sh`.
8. Запустите: `./analyze_dir.sh /home/user` и `./analyze_dir.sh /nonexistent`.

### Пример решения:

```bash
#!/bin/bash
# Анализ директории

if [ $# -ne 1 ]; then
    echo "Использование: $0 <путь_к_директории>"
    exit 1
fi

directory="$1"

if [ ! -d "$directory" ]; then
    echo "Директория '$directory' не существует." >&2
    echo "$(date): Директория '$directory' не существует." >> errors.log
    exit 1
fi

echo "Анализируем директорию: $directory"
echo ""

# Перенаправляем вывод и ошибки
ls -l "$directory" > output.txt 2> errors.log

echo "Список файлов сохранён в output.txt"
echo "Ошибки сохранены в errors.log"

# Подсчитываем количество файлов и директорий
file_count=$(ls -l "$directory" | grep "^-" | wc -l)
dir_count=$(ls -l "$directory" | grep "^d" | wc -l)

echo ""
echo "=== Статистика ==="
echo "Файлов: $file_count"
echo "Директорий: $dir_count"
```

## Заключение

Вы узнали, как:

- Работают стандартные дескрипторы файлов: `STDIN`, `STDOUT`, `STDERR`.
- Перенаправлять ввод и вывод с помощью `<`, `>`, `>>`.
- Перенаправлять ошибки с помощью `2>`.
- Объединять вывод и ошибки с помощью `2>&1`.

Теперь вы можете писать более надёжные скрипты, которые корректно обрабатывают данные и ошибки, и не мешают друг другу на экране.
