## Введение

Вы уже умеете перенаправлять стандартные потоки (`STDIN`, `STDOUT`, `STDERR`) с помощью операторов `>`, `<` и команды `exec`. Но что, если нужно работать с **несколькими файлами одновременно**? Например, читать данные из одного файла, а писать результаты в другой — и при этом не терять возможность ввода с клавиатуры?

Для этого в Linux и Bash есть мощный инструмент — **альтернативные дескрипторы файлов** (от `3` до `9`). Вы можете назначить им любые файлы и использовать их в скрипте.

Этот урок поможет вам:

- Понять, как создавать и использовать альтернативные дескрипторы.
- Читать и писать в файлы одновременно.
- Закрывать дескрипторы, чтобы освободить ресурсы.
- Проверять открытые дескрипторы с помощью команды `lsof`.

## Создание входного дескриптора файла

### Что это такое?

Вы можете сохранить текущее состояние `STDIN` в альтернативном дескрипторе, перенаправить `STDIN` на чтение из файла, а затем восстановить `STDIN` обратно.

### Чтение из файла и возврат к клавиатуре

Файл `read_and_restore.sh`:

```bash
#!/bin/bash
# Сохраняем STDIN в дескрипторе 6, читаем из файла, возвращаемся к клавиатуре

exec 6<&0          # Сохраняем текущий STDIN в дескрипторе 6
exec 0< data.txt   # Перенаправляем STDIN на чтение из файла

count=1
while read line; do
    echo "Строка $count: $line"
    ((count++))
done

exec 0<&6          # Восстанавливаем STDIN из дескриптора 6
exec 6<&-          # Закрываем дескриптор 6

echo ""
read -p "Вы закончили? (y/n): " answer
case "$answer" in
    [Yy])
        echo "До свидания!"
        ;;
    [Nn])
        echo "Это конец."
        ;;
    *)
        echo "Неизвестный ответ. До свидания."
        ;;
esac
```

![](https://ucarecdn.stepik.net/f392f718-7034-476c-a84f-796198343805/)

Мы прочитали данные из файла, а затем вернулись к вводу с клавиатуры.

Используйте `exec N<&0` для сохранения `STDIN` и `exec 0<&N` для его восстановления.

## Создание дескриптора для чтения и записи

### Что это такое?

Вы можете открыть один дескриптор для **одновременного чтения и записи** в файл. Это полезно, когда нужно считывать данные из файла, изменять их и записывать обратно.

### Чтение и запись в один файл

Файл `read_write_file.sh`:

```bash
#!/bin/bash
# Открываем дескриптор 3 для чтения и записи в файл

exec 3<> data.txt

# Читаем первую строку
read -u 3 first_line
echo "Прочитано: $first_line"

# Записываем новую строку
echo "Новая строка" >&3

# Читаем оставшиеся строки
while read -u 3 line; do
    echo "Остаток: $line"
done

exec 3>&-  # Закрываем дескриптор
```

![](https://ucarecdn.stepik.net/a4d9fcbe-1696-4ff8-afdf-2c455c6d2922/)

Дескриптор `3` имеет внутренний указатель. После чтения первой строки указатель находится в начале второй строки. Когда мы пишем новую строку, она записывается в это место, сдвигая остальные строки.

Будьте осторожны при использовании одного дескриптора для чтения и записи — это может привести к непредсказуемым результатам.

## Закрытие дескрипторов файлов

### Почему это важно?

Если вы открываете дескриптор файла, он остаётся открытым до завершения скрипта. Это может привести к утечке ресурсов или ошибкам при повторном открытии файла.

### Закрытие дескриптора

Файл `close_descriptor.sh`:

```bash
#!/bin/bash
# Открываем дескриптор 3 для записи в файл

exec 3> output.txt

echo "Это сообщение в файле." >&3

exec 3>&-  # Закрываем дескриптор 3

# Попытка записать в закрытый дескриптор
echo "Это не сработает." >&3
```

![](https://ucarecdn.stepik.net/fae51066-45e7-4428-91f7-9a5ed34ae218/)

Команда `exec 3>&-` закрыла дескриптор `3`, и попытка записи в него вызвала ошибку.

Всегда закрывайте дескрипторы, которые больше не нужны — это хорошая практика.

## Просмотр открытых дескрипторов с помощью `lsof`

### Что это такое?

Команда `lsof` (List Open Files) показывает все открытые файлы в системе — включая дескрипторы процессов. Это полезно для отладки.

### Просмотр открытых дескрипторов

Файл `check_descriptors.sh`:

```bash
#!/bin/bash
# Проверяем открытые дескрипторы

echo "=== Открытые дескрипторы для текущего процесса ==="
lsof -a -p $$ -d 0,1,2,3

echo ""
echo "=== Содержимое файла output.txt ==="
cat output.txt
```

![](https://ucarecdn.stepik.net/eba171bf-e022-4d48-8343-2503b71bf42e/)

Команда `lsof -a -p $$ -d 0,1,2,3` показывает открытые дескрипторы для текущего процесса (`$$` — PID процесса).

Используйте `lsof` для отладки — например, чтобы проверить, какие файлы открыты вашим скриптом.

## Практическое задание: создайте скрипт «Обработка логов»

### Цель:

Написать скрипт `process_logs.sh`, который:

1. Открывает файл `input.log` для чтения (дескриптор 3).
2. Открывает файл `output.log` для записи (дескриптор 4).
3. Читает строки из `input.log`.
4. Если строка содержит слово "ERROR", записывает её в `output.log`.
5. Закрывает дескрипторы.
6. Выводит статистику.

### Инструкция:

1. Создайте файл `process_logs.sh`.
2. Добавьте shebang `#!/bin/bash`.
3. Используйте `exec 3< input.log` для открытия файла на чтение.
4. Используйте `exec 4> output.log` для открытия файла на запись.
5. Используйте `read -u 3 line` для чтения строк.
6. Используйте `[[ "$line" == *ERROR* ]]` для проверки наличия слова.
7. Используйте `echo "$line" >&4` для записи в файл.
8. Закройте дескрипторы: `exec 3<&-` и `exec 4>&-`.
9. Сохраните, дайте права: `chmod u+x process_logs.sh`.
10. Создайте тестовый файл `input.log` и запустите: `./process_logs.sh`.

### Пример решения:

```bash
#!/bin/bash
# Обработка логов

# Открываем файлы
exec 3< input.log
exec 4> output.log

error_count=0

while read -u 3 line; do
    if [[ "$line" == *ERROR* ]]; then
        echo "$line" >&4
        ((error_count++))
    fi
done

# Закрываем дескрипторы
exec 3<&-
exec 4>&-

echo "Обработка завершена."
echo "Найдено ошибок: $error_count"
echo "Результат записан в output.log"
```
