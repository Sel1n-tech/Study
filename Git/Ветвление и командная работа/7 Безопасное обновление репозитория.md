
**`git fetch`** — это команда для получения изменений **из удалённого репозитория**, но **без автоматического слияния** с вашей текущей веткой. Она безопасна и не меняет вашу рабочую директорию.

## **Что делает `git fetch`?**

- Скачивает все новые коммиты, ветки и теги из удалённого репозитория.
    
- Обновляет **удалённые ссылки** (например, `origin/main`), но **не трогает** ваши локальные ветки (`main`).
    
- Показывает, насколько удалённые ветки ушли вперёд или отстали от ваших.
    

## **Синтаксис**

```php-template
git fetch <remote-name> [<branch>]
```

- `<remote-name>` — имя удалённого репозитория (по умолчанию `origin`).
    
- `<branch>` — конкретная ветка (если не указать — обновит все ветки).
    

## **После `git fetch`**

- Вы можете **сравнить** изменения через `git diff` или `git log`:
    

`**git diff main origin/main** # посмотреть различия`

`**git log master..origin/master**  # что есть в origin, но нет у вас`

- Вручную **слить** изменения:
    

**`git merge origin/main`**

- Или **переключиться** на обновлённую ветку:
    

**`git checkout origin/master`**

## **Отличие от `git pull`**

|`git fetch`|`git pull`|
|---|---|
|Только загружает изменения|Загружает **и сразу сливает**|
|Не меняет рабочую директорию|Может вызвать конфликты|
|Безопасен для проверки изменений|Может сломать код|

По сути, `git **pull** = git **fetch** + git **merge**`.

## **Настройка авто-fetch**

Добавьте в глобальный конфиг:

`git config --global --add remote.origin.fetch "+refs/pull/*/head:refs/remotes/origin/pr/*"`

Теперь можно получать PR-ветки из GitHub/GitLab.

## **Когда использовать?**

- **Перед слиянием** — чтобы увидеть, что изменилось в удалённой ветке.
    
- **Для синхронизации** — когда нужно обновить локальные ссылки без риска.
    
- **В CI/CD** — чтобы проверить актуальность кода перед сборкой.
    

### **Визуализация до и после**

**До `git fetch`:**

Ваш локальный репо:     A — B — C (master)
Удалённый origin:       A — B — D (origin/master)

**После `git fetch`:**

Ваш локальный репо:     A — B — C (master) ← теперь знает про D
Удалённый origin:       A — B — D (origin/master)

## **Cценарии использования**

**С `git fetch` + `git merge`:**

**git fetch origin**           # Только загружаем данные
**git diff origin/master**     # Смотрим, что изменилось
**git merge origin/master **   # Сливаем осмысленно

✅ Вы видите изменения перед слиянием.  
✅ Можете отменить операцию, если что-то не так.

### С `git pull` (который = `fetch` + `merge`):

**git pull origin master**     # Сразу загружает и сливает

❌ Риск неожиданных конфликтов.  
❌ Нет времени на анализ изменений.
