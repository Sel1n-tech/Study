## Введение

Вы уже умеете запускать скрипты в фоновом режиме и управлять ими с помощью `jobs`, `fg` и `bg`. Но что, если нужно **управлять приоритетом** — например, сделать так, чтобы скрипт работал медленнее, не мешая другим процессам? Или наоборот — дать ему больше ресурсов?

Для этого в Linux есть команды:

- **`nice`** — для установки приоритета при запуске.
- **`renice`** — для изменения приоритета запущенного процесса.
- **`at`** — для запуска задачи в определённое время.

Этот урок поможет вам:

- Понять, что такое приоритеты процессов.
- Научиться изменять приоритеты с помощью `nice` и `renice`.
- Запускать задачи в определённое время с помощью `at`.

## Что такое приоритеты процессов?

### Определение

В Linux ядро управляет распределением времени процессора (CPU) между всеми запущенными процессами. Каждый процесс имеет **приоритет**, который определяет, сколько времени он получит от CPU.

### Диапазон приоритетов:

|Приоритет|Описание|
|---|---|
|`-20`|Самый высокий приоритет (процесс получает максимум CPU).|
|`0`|Стандартный приоритет (по умолчанию).|
|`+19`|Самый низкий приоритет (процесс получает минимум CPU).|

Чем ниже число, тем выше приоритет. Например, `-20` — самый важный, `+19` — самый низкий.

## Команда `nice` — установка приоритета при запуске

### Что это такое?

Команда `nice` позволяет запустить процесс с заданным приоритетом.

### Синтаксис:

```bash
nice [опции] команда
```

Обычные пользователи могут только **понижать** приоритет (увеличивать значение), но не повышать. Для повышения приоритета нуны права суперпользователя.

### Запуск с низким приоритетом

Файл `low_priority.sh`:

```bash
#!/bin/bash
# Скрипт с низким приоритетом

echo "Начинаю работу..."
for i in {1..5}; do
    echo "Шаг $i"
    sleep 10
done
echo "Работа завершена."
```

Мы запустили скрипт с приоритетом `12` — он будет получать меньше CPU, чем процессы со стандартным приоритетом `0`.

## Команда `renice` — изменение приоритета запущенного процесса

### Что это такое?

Команда `renice` позволяет изменить приоритет уже запущенного процесса.

### Синтаксис:

```bash
renice [опции] приоритет -p PID
```

Только владелец процесса или root может изменять его приоритет.

###  Изменение приоритета запущенного процесса

Файл `change_priority.sh`:

```bash
#!/bin/bash
# Изменение приоритета запущенного процесса

echo "Начинаю долгую работу..."
while true; do
    echo "Работаю..."
    sleep 10
done
```

Мы изменили приоритет процесса с `0` на `10`.

## Команда `at` — планирование задач

### Что это такое?

Команда `at` позволяет запустить задачу в определённое время — например, через 5 минут или в 10:00 утра.

### Синтаксис:

```bash
at [опции] время
```

По умолчанию `at` отправляет вывод на почту. Чтобы избежать этого, перенаправьте вывод в файл или используйте `-M`.

### Запуск задачи через 5 минут

Файл `scheduled_script.sh`:

```bash
#!/bin/bash
# Задача, запланированная на будущее

echo "Задача выполнена в $(date)"
```

Пример запуска:

```no-highlight
at now + 5 minutes
at> ./scheduled_script.sh > output.txt
at> <EOT>
```

Задача будет запущена через 5 минут и результат запишется в `output.txt`.

## Практическое задание: создайте скрипт «Планировщик задач»

### Цель:

Написать скрипт `scheduler.sh`, который:

1. Запрашивает у пользователя:
    - Время запуска (например, `now + 10 minutes`).
    - Имя файла с командами.
2. Планирует выполнение файла в указанное время.
3. Сохраняет вывод в файл `schedule.log`.

### Инструкция:

1. Создайте файл `scheduler.sh`.
2. Добавьте shebang `#!/bin/bash`.
3. Запросите время и имя файла.
4. Используйте `at` для планирования.
5. Перенаправьте вывод в файл.
6. Сохраните, дайте права: `chmod u+x scheduler.sh`.
7. Запустите: `./scheduler.sh`.

### Пример решения:

```bash
#!/bin/bash
# Планировщик задач

echo -n "Введите время запуска (например, 'now + 5 minutes'): "
read time

echo -n "Введите имя файла с командами: "
read filename

if [ ! -f "$filename" ]; then
    echo "Файл $filename не найден."
    exit 1
fi

echo "Планирую выполнение $filename в $time..."
at "$time" << EOF
./$filename > schedule.log 2>&1
EOF

echo "Задача запланирована."
```
