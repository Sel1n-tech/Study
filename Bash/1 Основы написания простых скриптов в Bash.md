## Введение

Допустим, вы уже умеете работать с командной строкой (CLI) и запускать отдельные команды. Но настоящая мощь Unix-подобных систем раскрывается, когда вы начинаете объединять команды в скрипты — небольшие программы, которые автоматизируют повторяющиеся задачи. Этот урок поможет вам сделать первый шаг в создании собственных shell-скриптов.

## Запуск нескольких команд сразу

### Что это такое?

Вместо того чтобы вводить команды по одной, вы можете объединить их в одну строку, разделяя точкой с запятой `;`. Это позволяет выполнить несколько действий за один раз.

```bash
date; who
```

Это удобно для быстрых операций, но не подходит для сложных задач. Все команды выполняются последовательно, независимо от успеха предыдущей.

## Создание файла скрипта

### Почему это нужно?

Вводить длинные цепочки команд каждый раз неудобно. Лучше сохранить их в файле — так называемом **_shell-скрипте_**. Тогда вы сможете запускать его снова и снова.

### Шаг 1: Создайте файл

Откройте текстовый редактор (например, `nano`, `vim` или `gedit`) и создайте файл, например, `test1`.

Обычно vim доступен в любом дистрибутиве. В некоторых системах доступен через Vi.

![](https://ucarecdn.stepik.net/2c62465f-bc76-4892-958a-69b13fea201f/)

Самый простой редактор - nano. Если нет, можно установить.

В производных от Red Hat это можно сделать, например, так:

![](https://ucarecdn.stepik.net/a350ac49-a5f8-4d69-8e88-5af0e74715a7/)

Для простоты будем использовать именно nano:

![](https://ucarecdn.stepik.net/245403db-26f6-46c4-99d9-3e8a5f8053c1/)

### Шаг 2: Добавьте "шебанг"

Первая строка любого скрипта должна указывать, какой интерпретатор использовать. Для bash это:

```bash
#!/bin/bash
```

Это называется **shebang**. Он говорит системе: «Запусти этот файл с помощью `/bin/bash`».

Добавьте нужные команды, каждую с новой строки:

![](https://ucarecdn.stepik.net/3fd01bf3-7091-4443-aa11-cecea74a87a1/)

Ctrl+O - записать в файл.

Ctrl+X - выйти из редактора.

Комментарии (строки, начинающиеся с `#`) игнорируются при выполнении. Используйте их, чтобы описывать, что делает ваш код — это очень помогает при возврате к нему через время!

## Запуск скрипта — первые трудности

Если вы просто наберёте `test1` в терминале, получите ошибку:

![](https://ucarecdn.stepik.net/efc144af-45b8-4f93-855e-ef2d228a85ac/)

### Почему так произошло?

Две основные причины.

**Система не знает, где искать ваш файл.**

По умолчанию оболочка ищет команды только в определённых каталогах, перечисленных в переменной окружения `PATH`.

![](https://ucarecdn.stepik.net/bff0d9fb-7c46-45a4-ab6e-bf11f03c30a9/)

Ваш скрипт находится в текущем каталоге, который не входит в `PATH`.

**Решение 1:** укажите полный путь к файлу.

![](https://ucarecdn.stepik.net/398644ad-e712-4561-818a-29b8a99a8388/)

Обратите внимание: `./` означает «текущий каталог». Без этого префикса система не будет искать файлы здесь.

И как вы могли заметить

**У вас нет прав на выполнение файла.**

По умолчанию, при создании файла, у него есть права только на чтение и запись (`rw-r--r--`).

![](https://ucarecdn.stepik.net/64f34af1-674b-48ed-b3d1-7b3c831924b1/)

**Решение 2:** дайте себе право на выполнение с помощью команды `chmod`:

![](https://ucarecdn.stepik.net/9e9c5698-e0f4-42d9-9962-c51a1886a46e/)

`u+x` означает: добавить право на выполнение (`x`) для владельца файла (`u`).

Теперь можно запускать:

![](https://ucarecdn.stepik.net/57009042-1cac-4bc2-b17c-25de755c661f/)

**Готово!** Если всё сделано правильно, скрипт должен успешно выполниться.

## Вывод сообщений пользователю — команда `echo`

Часто нужно выводить понятные сообщения, чтобы пользователь понимал, что происходит.

### Простой вывод

```bash
echo "Это тест"
```

![](https://ucarecdn.stepik.net/b6ac28d1-808d-4f4f-86a8-b6cb63140fb6/)

### Работа с кавычками

Будьте осторожны с кавычками внутри строки. Используйте разные типы кавычек, чтобы избежать ошибок.

**Правильно:**

```bash
echo "Это тест, чтобы проверить, внимательны ли вы"
echo 'А вот текст в "кавычках".'
```

![](https://ucarecdn.stepik.net/8667ab6f-3326-48d2-a8b9-13f904abac78/)

**Неправильно (если не использовать разные кавычки):**

```bash
echo Let's see if this'll work  # Может вызвать ошибку в некоторых случаях
```

![](https://ucarecdn.stepik.net/15e7cde9-7795-42df-a416-fe04af144932/)

Если внутри строки есть апостроф `'`, используйте двойные кавычки `"` и наоборот.

## Улучшение скрипта — добавляем `echo`

Давайте улучшим наш скрипт `test1`, добавив поясняющие сообщения.

**Обновлённый скрипт:**

```bash
#!/bin/bash
# Этот скрипт показывает дату и кто вошёл в систему
echo "Кто я:"
whoami
echo "Время и дата:"
date
echo "Посмотрим, кто вошёл в систему:"
who
```

Запустите его:

![](https://ucarecdn.stepik.net/e71ec8de-6565-4e5b-b44b-879ade249064/)

## Вывод без перевода строки — параметр `-n`

Иногда нужно, чтобы вывод команды продолжался на той же строке, что и сообщение `echo`. Для этого используется параметр `-n`.

**Пример:**

```bash
echo -n "Время и дата: "
date
```

**Результат:**

![](https://ucarecdn.stepik.net/4c5a62ce-64d0-455b-ac65-0b47dbe7fd7f/)

Не забывайте ставить пробел в конце строки после `-n`, иначе текст слипнется.
