Имена пакетов играют точно такую же роль, как и в Java. Они позволяют нам разделить кодовую базу без каких-либо конфликтов. Классы Groovy должны указывать свой пакет перед определением класса, иначе предполагается пакет по умолчанию.

Определение пакета очень похоже на Java:

```go
package com.yoursite // определение пакета с именем com.yoursite
```

  
Чтобы сослаться на некоторый класс Foo в пакете com.yoursite.com, вам нужно будет использовать полное имя com.yoursite.com.Foo, иначе вы можете использовать оператор импорта, как мы увидим ниже.

## Импорт

Чтобы сослаться на любой класс, вам нужна квалифицированная ссылка на его пакет. Groovy следует за идеей Java, позволяющей оператору импорта разрешать ссылки на классы.

Например, Groovy предоставляет несколько классов построителей, таких как MarkupBuilder. MarkupBuilder находится внутри пакета groovy.xml, поэтому для использования этого класса его необходимо импортировать, как показано ниже:

```java
// importing the class MarkupBuilder
import groovy.xml.MarkupBuilder

// using the imported class to create an object
def xml = new MarkupBuilder()
```

  
Простой импорт — это оператор импорта, в котором вы полностью определяете имя класса вместе с пакетом. Например, оператор импорта import groovy.xml.MarkupBuilder в приведенном ниже коде представляет собой простой импорт, который напрямую ссылается на класс внутри пакета.

Groovy, как и Java, предоставляет специальный способ импорта всех классов из пакета с помощью *, так называемый звездообразный импорт. MarkupBuilder — это класс, который находится в пакете groovy.xml вместе с другим классом, называемым StreamingMarkupBuilder. 

Возможность статического импорта Groovy позволяет вам ссылаться на импортированные классы, как если бы они были статическими методами вашего собственного класса:

```javascript
import static Boolean.FALSE
```

Статическое псевдоним импорта  
Статический импорт с ключевым словом as обеспечивает элегантное решение проблем с пространством имен. Предположим, вы хотите получить экземпляр Calendar, используя его метод getInstance(). Это статический метод, поэтому мы можем использовать статический импорт. Но вместо того, чтобы каждый раз вызывать getInstance(), что может ввести в заблуждение, если отделить его от имени класса, мы можем импортировать его с псевдонимом, чтобы повысить читаемость кода:

```csharp
import static Calendar.getInstance as now

println (now().class == Calendar.getInstance().class)
```

2.1. Импорт по умолчанию  
Импорт по умолчанию — это импорт, который язык Groovy предоставляет по умолчанию. Например, посмотрите на следующий код:

```javascript
new Date()
```

  
В том же коде на Java требуется оператор импорта для класса Date, например: import java.util.Date. Groovy по умолчанию импортирует эти классы.

Следующие импорты добавлены groovy для вас:

```java
import java.lang.*
import java.util.*
import java.io.*
import java.net.*
import groovy.lang.*
import groovy.util.*
import java.math.BigInteger
import java.math.BigDecimal
```

Это сделано потому, что чаще всего используются классы из этих пакетов. Импортируя этот шаблонный код, он сокращается.
