## Введение

Вы уже умеете перенаправлять вывод команд в файлы (`>` и `>>`) и ошибки (`2>`) с помощью операторов перенаправления. Но что, если нужно перенаправить **весь вывод** скрипта в файл? Или прочитать данные из файла не через `cat`, а напрямую?

Для этого в Bash есть мощный инструмент — команда **`exec`**. Она позволяет **постоянно** перенаправить стандартные потоки ввода/вывода на всё время выполнения скрипта.

Этот урок поможет вам:

- Понять разницу между временным и постоянным перенаправлением.
- Использовать `exec` для перенаправления `STDOUT` и `STDERR`.
- Читать данные из файла с помощью `exec`.
- Создавать сложные конфигурации ввода/вывода с помощью альтернативных дескрипторов файлов.

## Временное перенаправление

### Что это такое?

Временное перенаправление — это когда вы перенаправляете вывод одной команды в файл, но следующая команда снова использует стандартный вывод (на экран).

### Временное перенаправление ошибок

Файл `temp_redirect.sh`:

```bash
#!/bin/bash
# Временное перенаправление ошибок

echo "Это сообщение на экране."
echo "Это ошибка" >&2
echo "Ещё одно сообщение на экране."
```

![](https://ucarecdn.stepik.net/337fe201-691b-416b-b690-36da43efa02d/)

Сообщение об ошибке (`>&2`) выведено на экран, как и обычный вывод.

### Перенаправление ошибок в файл

Файл `temp_error_to_file.sh`:

```bash
#!/bin/bash
# Перенаправляем только ошибку в файл

echo "Это сообщение на экране."
echo "Это ошибка" >&2 > error.txt
echo "Ещё одно сообщение на экране."
```

![](https://ucarecdn.stepik.net/1606d5b6-180e-4d7a-bb5f-5b5d885ec9d8/)

## Постоянное перенаправление с помощью `exec`

### Что это такое?

Команда `exec` позволяет **постоянно** перенаправить стандартные потоки ввода/вывода. Это значит, что все последующие команды в скрипте будут использовать новые потоки.

### Постоянное перенаправление `STDOUT`

Файл `permanent_stdout.sh`:

```bash
#!/bin/bash
# Постоянно перенаправляем STDOUT в файл

exec > output.txt

echo "Это сообщение будет в файле."
echo "И это тоже."
echo "Все последующие сообщения идут в файл."

# Выводим содержимое файла
cat output.txt
```

![](https://ucarecdn.stepik.net/cb0fb788-a57a-4759-be01-9b30528d35c4/)

Все команды после `exec > output.txt` пишут в файл, даже `cat`.

### Постоянное перенаправление `STDERR`

Файл `permanent_stderr.sh`:

```bash
#!/bin/bash
# Постоянно перенаправляем STDERR в файл

exec 2> errors.log

echo "Это сообщение на экране."
echo "Это ошибка" >&2
echo "Ещё одно сообщение на экране."

# Выводим содержимое файла ошибок
cat errors.log
```

![](https://ucarecdn.stepik.net/954ed503-ee4f-49ff-93cb-5ed1f1ddb012/)

Ошибка (`>&2`) теперь записывается в файл `errors.log`.

## Перенаправление в середине скрипта

Вы можете изменить перенаправление в любой момент скрипта с помощью `exec`.

### Изменение перенаправления

Файл `change_redirect.sh`:

```bash
#!/bin/bash
# Меняем перенаправление в середине скрипта

echo "Это сообщение на экране."

# Перенаправляем STDOUT в файл
exec > output.txt

echo "Это сообщение в файле."

# Перенаправляем STDERR в другой файл
exec 2> errors.log

echo "Это сообщение в файле output.txt."
echo "Это ошибка" >&2

# Возвращаемся к стандартному выводу
exec > /dev/tty

echo "Это снова на экране."
```

![](https://ucarecdn.stepik.net/50cc552c-ea40-4fc6-8f5b-1f6cc1e14d2d/)

Мы смогли изменить перенаправление несколько раз в одном скрипте.

## Чтение данных из файла с помощью `exec`

Команда `exec` также позволяет перенаправить `STDIN` на чтение из файла. Это удобно, когда нужно обработать данные из файла без использования `cat` или `while read`.

### Чтение из файла

Файл `read_from_file.sh`:

```bash
#!/bin/bash
# Читаем данные из файла с помощью exec

exec < data.txt

count=1
while read line; do
    echo "Строка $count: $line"
    ((count++))
done

echo "Обработка файла завершена."
```

![](https://ucarecdn.stepik.net/e865decc-3344-408c-9636-638fb93677c4/)

Команда `exec < data.txt` перенаправляет `STDIN` на чтение из файла `data.txt`.

## Альтернативные дескрипторы файлов

В Linux доступны дополнительные дескрипторы файлов (от `3` до `9`).

Вы можете назначить им любые файлы и использовать их в скрипте.

### Использование альтернативного дескриптора

Файл `alt_descriptor.sh`:

```bash
#!/bin/bash
# Используем альтернативный дескриптор файла

exec 3> output.txt

echo "Это сообщение на экране."
echo "Это сообщение в файле output.txt" >&3
echo "Это снова на экране."

# Закрываем дескриптор
exec 3>&-

echo "Дескриптор 3 закрыт."
```

![](https://ucarecdn.stepik.net/5dcadf9a-e35c-4786-9a06-fc7542ea8aba/)

Дескриптор `3` был назначен файлу `output.txt`, и все сообщения, отправленные в `&3`, записались в этот файл.

## Практическое задание: создайте скрипт «Логирование действий»

### Цель:

Написать скрипт `log_actions.sh`, который:

1. Перенаправляет весь вывод (`STDOUT`) в файл `output.log`.
2. Перенаправляет все ошибки (`STDERR`) в файл `errors.log`.
3. Выводит текущее время и список файлов в директории `/home/user`.
4. Если директория не существует — выводит сообщение об ошибке.
5. В конце выводит статистику.

### Инструкция:

1. Создайте файл `log_actions.sh`.
2. Добавьте shebang `#!/bin/bash`.
3. Используйте `exec` для перенаправления `STDOUT` и `STDERR`.
4. Проверьте существование директории: `if [ ! -d "/home/user" ]; then ... exit 1; fi`.
5. Используйте `ls -l` для получения списка файлов.
6. Сохраните, дайте права: `chmod u+x log_actions.sh`.
7. Запустите: `./log_actions.sh`.

### Пример решения:

```bash
#!/bin/bash
# Логирование действий

# Перенаправляем STDOUT и STDERR
exec > output.log 2> errors.log

echo "=== Начало работы скрипта ==="
echo "Текущее время: $(date)"

directory="/home/user"

if [ ! -d "$directory" ]; then
    echo "Директория '$directory' не существует." >&2
    exit 1
fi

echo "Список файлов в директории $directory:"
ls -l "$directory"

echo "=== Конец работы скрипта ==="
```
