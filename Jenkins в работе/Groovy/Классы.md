Классы Groovy очень похожи на классы Java и совместимы с классами Java на уровне JVM. У них могут быть методы, поля и свойства . Классы и члены класса могут иметь те же модификаторы (public, protected, private, static и т. д.), что и в Java, с некоторыми незначительными отличиями на уровне исходного кода.

Основные отличия классов Groovy от их аналогов в Java:

- Классы или методы без модификатора видимости автоматически становятся общедоступными 
- Поля без модификатора видимости автоматически превращаются в свойства, что приводит к менее подробному коду, поскольку не нужны явные методы получения и установки. 
- Классы не обязательно должны иметь то же базовое имя, что и их определения исходных файлов, но это настоятельно рекомендуется в большинстве сценариев
- Один исходный файл может содержать один или несколько классов (но если файл содержит какой-либо код, не относящийся к классу, он считается скриптом). Скрипты — это просто классы с некоторыми специальными соглашениями, и они будут иметь то же имя, что и их исходный файл (поэтому не включайте определение класса в сценарий с тем же именем, что и исходный файл сценария).

В следующем коде представлен пример класса.

```java
class Person {   // начало класса с именем Person
    String name  // строковое поле с именем name                     
    Integer age  // целочисленное поле с именем age

    def increaseAge(Integer years) {  // это определение метода класса Person
        this.age += years
    }
}
```

## Обычный класс

Обычный классы относятся к классам верхнего уровня. Это означает, что они могут быть созданы без ограничений из любых других классов или скриптов. Таким образом, они могут быть только общедоступными (даже если ключевое слово public может быть скрыто). Классы создаются путем вызова их конструкторов с использованием нового ключевого слова, как в следующем коде.

```java
def p = new Person()
```

## Внутренний класс

Внутренние классы определяются внутри других классов. Охватывающий класс может использовать внутренний класс, как обычно. С другой стороны, внутренний класс может получить доступ к членам внешнего его класса, даже если они закрыты. Классы, отличные от внешнего класса, не имеют доступа к внутренним классам. Вот пример:

```java
class Outer {
    private String privateStr = 'outer'

    def callInnerMethod() {
        new Inner().methodA()   // создается экземпляр внутреннего класса и вызывается его метод    
    }

    class Inner {      // определение внутреннего Inner класса, внутри внешнего Outer класса        
        def methodA() {
            // будучи закрытым, доступ к полю вшешнего класса есть у внутреннего классом
            println "${privateStr}."  
        }
    }
}
def o = new Outer()
o.callInnerMethod()
```

Есть несколько причин для использования внутренних классов:

- Они повышают инкапсуляцию, скрывая внутренний класс от других классов, которым не нужно об этом знать. Это также приводит к более чистым пакетам и рабочим пространствам.
- Они обеспечивают хорошую организацию, группируя классы, используемые только одним классом.
- Они приводят к более удобному для сопровождения коду, поскольку внутренние классы находятся рядом с классами, которые их используют.

Обычно внутренний класс является реализацией некоторого интерфейса, методы которого необходимы внешнему классу. 

## Анонимный внутренний класс

Предыдущий пример внутреннего класса (Inner2) можно упростить с помощью анонимного внутреннего класса. Та же функциональность может быть достигнута с помощью следующего кода:

```java
class Outer2 {
    private String privateStr = 'some string'

    def startThread() {
        new Thread(new Runnable() {    // безымяный внутрений класс обратите внимание на ()  
            void run() {
                println "${privateStr}."
            }
        }).start() // метод start вызывается              
    }
}
def o = new Outer2()
o.startThread()
```

Таким образом, не было необходимости определять новый класс для однократного использования.

## Абстрактный класс

Абстрактные классы представляют собой общую архитектуру, потому они не могут быть созданы, поскольку создаются для подклассов. Их члены включают поля/свойства и абстрактные или контретные методов. Абстрактные методы не имеют реализации объявленых в них методов и должны реализовываться конкретными подклассами.

```java
// абстрактные классы должны быть объявлены с ключевым словом abstract

abstract class Abstract {         
    String name
   
    // абстрактные методы также должны быть объявлены с помощью ключевого слова abstract
    abstract def abstractMethod() 

    def concreteMethod() {
        println 'concrete'
    }
}
```

- Абстрактные классы обычно сравнивают с интерфейсами. Есть как минимум два важных различия.
- Во-первых, в то время как абстрактные классы могут содержать поля/свойства и конкретные методы, интерфейсы могут содержать только абстрактные методы (сигнатуры методов).
- А во вторых, один класс может реализовывать несколько интерфейсов, тогда как он может расширять только один класс, абстрактный или нет.

## Суперклассы

Родительские классы имеют общие видимые поля, свойства или методы с дочерними классами. Дочерний класс может иметь не более одного родительского класса. Ключевое слово **extends** используется непосредственно перед указанием типа суперкласса.

## Наследование

Наследование в Groovy напоминает наследование в Java.

Чтобы объявить один класс наследником от другого, надо использовать после имени класса-наследника ключевое слово **extends**, после которого идет имя базового класса. Получаем доступ ко всем полям и методам базового класса. Используя наследование, можно создать общий класс, которые определяет характеристики, общие для набора связанных элементов. Затем вы можете наследоваться от него и создать новый класс, который будет иметь свои уникальные характеристики. Главный наследуемый класс в Java называют суперклассом (родительским). Наследующий класс называют подклассом(дочернего класса)

Если в базовом классе определены конструкторы, то в конструкторе производного классы необходимо вызвать один из конструкторов базового класса с помощью ключевого слова `super`. При вызове конструктора после слова  в скобках идет перечисление передаваемых аргументов. При этом вызов конструктора базового класса должен идти в самом начале в конструкторе производного класса.

Классы, связанные посредством наследования, образуют иерархию наследования.

Общее поведение и элементы перемещаются вверх по иерархии, чтобы уменьшить дублирование. Специализации происходят в дочерних классах.

**Поддерживаются различные формы наследования:**

- наследование реализации, когда код (методы, поля или свойства) из суперкласса или из одного или нескольких признаков повторно используется дочерним классом
- наследование по контракту, когда класс обещает предоставить определенные абстрактные методы, определенные в суперклассе или определенные в одном или нескольких трейтах или интерфейсах.

**extends** — это ключевое слово, используемое для наследования свойств класса. Ниже приведен синтаксис ключевого слова extends. 

## Интерфейсы

Интерфейс определяет контракт, которому должен соответствовать класс.

Интерфейс только определяет список методов, которые необходимо реализовать, но не определяет реализацию метода. 

```java
// интерфейс должен быть объявлен с использованием ключевого слова interface

interface Shape {                                         
    void draw(String name)  // интерфейс определяет только сигнатуры методов, реализации НЕТ                               
}


```

Методы интерфейса всегда общедоступны. Использование защищенных`protected` или  `private`закрытых методов в интерфейсах является ошибкой.

Класс реализует интерфейс, если он определяет интерфейс в своем списке реализаций или если это делает любой из его суперклассов:

> **instanceof** проверяет, является ли объект подклассом некоторого класса.

```typescript

interface Shape {                                         
    void draw(String name)  // интерфейс определяет только сигнатуры методов, реализации НЕТ                               
}
// Прямоугольник объявляет интерфейс Shape с помощью ключевого слова Implements.
class Rectangle implements Shape {
    // Затем реализует требуемый метод draw(String name)               
    void draw(String name) {                               
        println "painted $name"
    }
}

def rectangle = new Rectangle()
// Любой экземпляр Rectangle также является экземпляром интерфейса Shape.
println rectangle instanceof Shape // вернет true



```

Интерфейс может расширять другой интерфейс:

```java
interface Shape {                                         
    void draw(String name)  // интерфейс определяет только сигнатуры методов, реализации НЕТ                               
}
// интерфейс ExtendedShape расширяет интерфейс Shape с помощью ключевого слова extends
interface ExtendedShape extends Shape {                 
    void delete(String name)
}
```

Стоит отметить, что для того, чтобы класс был экземпляром интерфейса, он должен быть явным.

Другими словами, Groovy не определяет структурную типизацию. Однако можно сделать так, чтобы экземпляр объекта реализовывал интерфейс во время выполнения, используя оператор приведения **as:**

```typescript
interface Shape {                                         
    void draw(String name)  // интерфейс определяет только сигнатуры методов, реализации НЕТ                               
}

class Triangle {
    void draw(String name) { println "Triangle ${name}" }
}

triangleDefault = new Triangle()
println triangleDefault instanceof Shape // вернет false
                           
triangleAsShape = triangleDefault as Shape                                
println triangleAsShape instanceof Shape  // вернет true
```

Интерфейсы Groovy не поддерживают реализацию по умолчанию, как интерфейсы Java 8.

# Члены класса

## **Конструктор**

**Конструкторы** — это специальные методы, используемые для инициализации объекта с определенным состоянием. Как и в случае с обычными методами, класс может объявить более одного конструктора, если каждый конструктор имеет уникальную сигнатуру типа.

Если объект не требует каких-либо параметров во время построения, он может использовать конструктор без аргументов. Если конструкторы не указаны, компилятор Groovy предоставит пустой конструктор без аргументов.

Groovy поддерживает два стиля вызова:

- позиционные параметры используются аналогично тому, как вы использовали бы конструкторы Java.
- именованные параметры позволяют указывать имена параметров при вызове конструктора.

## Позиционные параметры

Чтобы создать объект с использованием позиционных параметров, соответствующий класс должен объявить один или несколько конструкторов. В случае нескольких конструкторов каждый из них должен иметь уникальную сигнатуру типа. Конструкторы также можно добавить в класс с помощью аннотации **groovy.transform.TupleConstructor**

Как правило, после объявления хотя бы одного конструктора экземпляр класса может быть создан только путем вызова одного из его конструкторов. Стоит отметить, что в этом случае вы не можете нормально создать класс с именованными параметрами. Groovy поддерживает именованные параметры, если класс содержит конструктор без аргументов или предоставляет конструктор, который принимает аргумент Map в качестве первого  аргумента.

Есть три формы использования объявленного конструктора.

Первый — это обычный способ Java с ключевым словом **new**

Другие полагаются на приведение списков к желаемым типам. В этом случае можно выполнить принуждение с помощью ключевого слова as и статического ввода переменной.

```java
class Person {
    String name
    Integer age
    // Объявление конструктора
    Person(name, age) {          
        this.name = name
        this.age = age
    }
}

def p1 = new Person('Alex', 1)    // вызов конструктора, как в Java
def p2 = ['Valera', 2] as Person  // конструктор с использованием принуждения с ключевым словом as
Person p3 = ['Marie', 3]          // конструктор с использованием принуждения в присваивании
```

Именованные параметры  
Если конструктор не объявлен или конструктор без аргументов, можно создавать объекты, передавая параметры в виде карты (пары свойство/значение). Это может быть удобно в тех случаях, когда нужно разрешить несколько комбинаций параметров.

В противном случае, используя традиционные позиционные параметры, необходимо было бы объявить все возможные конструкторы. Также поддерживается наличие конструктора, в котором первым (и, возможно, единственным) аргументом является аргумент карты — такой конструктор также можно добавить с помощью аннотации groovy.transform.MapConstructor

```java
class Person {   // конструктор не объявлен в классе                               
    String name
    Integer age
}

def p1 = new Person()                 // в экземпляре не указаны параметры                           
def p2 = new Person(name: 'Valera')   // параметр name, указанный в экземпляре     
def p3 = new Person(age: 1)           // age параметр, указанный в экземпляре     
def person4 = new Person(name: 'Petro', age: 2) // параметры name & age, указанные в экземпляре
```

Однако важно подчеркнуть, что этот подход дает больше возможностей вызывающему конструктору, в то же время возлагая на него повышенную ответственность за корректность имен и типов значений. Таким образом, если требуется больший контроль, может быть предпочтительным объявление конструкторов с использованием позиционных параметров.

 Примечания:

- Хотя в приведенном выше примере нет конструктора, вы также можете указать конструктор без аргументов или конструктор, в котором первым аргументом является карта, чаще всего это единственный аргумент.
- Если конструктор не объявлен (или конструктор без аргументов), Groovy заменяет вызов именованного конструктора вызовом конструктора без аргументов, за которым следуют вызовы установщика для каждого предоставленного именованного свойства.
- Когда первым аргументом является карта, Groovy объединяет все именованные параметры в карту (независимо от порядка) и предоставляет карту в качестве первого параметра. Это может быть хорошим подходом, если ваши свойства объявлены как окончательные (поскольку они будут установлены в конструкторе, а не постфактум с помощью сеттеров).
- Вы можете поддерживать как именованное, так и позиционное построение, предоставив как позиционные конструкторы, так и конструктор без аргументов или Map.
- Вы можете поддерживать гибридное построение, имея конструктор, в котором первым аргументом является карта, но есть также дополнительные позиционные параметры. Используйте этот стиль с осторожностью.

## Методы

Метод состоит из

- Модификатор доступа (public, private, protected)
- один или несколько необязательных модификаторов (static, final)
- **Сигнатура** метода состоит из:
    - имя метода
    - набор параметров.
- Тип возвращаемого значения;
- Тело метода (блок кода)

Различают простые методы и статические методы :

- простые методы имеют доступ к данным объекта конкретного экземпляра (данного класса);
- статические методы не имеют доступа к данным объекта, и для их использования не нужно создавать экземпляры.

## Поля и свойства

### Поля

Поле — это член класса, интерфейса, в котором хранятся данные.

Поле, определенное в исходном файле Groovy, имеет:

- обязательный модификатор доступа (public, protected или private)
- один или несколько необязательных модификаторов (static, final, synchronized)
- необязательный тип
- обязательное имя

Давайте взглянем на пример полей класса

```java
class Person {
    String name    // создает резервное поле частного имени String, методы getName и setName                         
    int age       // создает резервное частное целое поле age, методы getAge и setAge                          
}

Person p = new Person()
p.setName('Valera')
println p.getName()
```

В данном примере вываются два метода которые не были определены!

_Это p.setName('Valera') и p.getName(), откуда они взялись?_

**Ответ:** Groovy сгенерирует геттеры/сеттеры соответствующим образом автоматически. Если свойство объявлено окончательным - **final**, сеттер не создается.

Доступ к свойствам осуществляется по имени, и геттер или сеттер будут вызываться прозрачно, если только код не находится в классе, который определяет свойство:

```java
class Person {
    String name
    void name(String name) {
        /* this.name будет напрямую обращаться к полю, 
           доступ к свойству осуществляется из класса, который его определяет. */
        this.name = "Wonder $name"      
    }
    String title() {
        /* аналогично доступ для чтения осуществляется непосредственно в поле имени */
        println this.name                       
    }
}
def p = new Person()

// доступ на запись к свойству осуществляется вне класса Person, будет неявно вызывать setName
p.name = 'Diana'   

// доступ для чтения к свойству осуществляется вне класса Person, будет неявно вызывать getName                     
println p.name == 'Diana' 
            
p.name('Woman') // вызовет метод name для Person, который выполняет прямой доступ к полю                           

// вызовет метод title для Person, который выполняет прямой доступ для чтения к полю
println (p.title() == 'Wonder Woman') 
```

Стоит отметить, что такое поведение прямого доступа к резервному полю выполняется для предотвращения переполнения стека при использовании синтаксиса доступа к свойству в классе, который определяет свойство.

Можно перечислить свойства класса благодаря полю мета-свойств экземпляра:

```java
class Person {
    String name
    String last
    int age
}
def p = new Person()
println p.properties.keySet() /// [class, age, last, name]
```

По соглашению Groovy распознает свойства, даже если нет резервного поля, при условии, что есть геттеры или сеттеры, соответствующие спецификации Java Beans. Например: 

```java
class PseudoProperties {
    // псевдосвойство "name"
    void setName(String name) {}
    String getName() {}

    // псевдо-свойство только для чтения "age"
    int getAge() { 42 }

    // псевдо-свойство только для записи "groovy"
    void setGroovy(boolean groovy) {  }
}
def p = new PseudoProperties()

//запись p.name разрешена, потому что это имя псевдо-свойства.
p.name = 'Foo'     

// чтение p.age разрешено, потому что существует свойство age псевдо-только для чтения.                      
println p.age == 42 

// запись p.groovy разрешена, потому что у groovy есть свойство псевдозаписи только для записи.                  
p.groovy = true   
```

### Соглашения об именах свойств

Обычно рекомендуется, чтобы первые две буквы имени свойства были строчными, а для свойств, состоящих из нескольких слов, использовался верблюжий регистр. В этих случаях сгенерированные геттеры и сеттеры будут иметь имя, образованное заглавными буквами имени свойства и добавлением префикса get или set (или, необязательно, «is» для логического геттера). Таким образом, getLength будет геттером для свойства length, а setFirstName — сеттером для свойства firstName. isEmpty может быть именем метода получения для свойства с именем empty. 

**Обратите внимание:**

Имена свойств, начинающиеся с заглавной буквы, будут иметь геттеры/сеттеры только с добавленным префиксом. Таким образом, свойство **Go** разрешено, даже если оно не соответствует рекомендуемым соглашениям об именах. Для этого свойства методы доступа будут **setGo** и **getGo**.

Следствием этого является то, что вам не разрешено иметь и свойство **go**, и свойство **Go**, поскольку у них будут методы доступа с одинаковыми именами.

Спецификация JavaBeans делает особый случай для свойств, которые обычно могут быть аббревиатурами.

К примеру если первые две буквы имени свойства в верхнем регистре URL, у свойства URL будет геттером getURL.

### Модификаторы полей (свойств)

Мы уже видели, что свойства определяются без модификатора видимости.

Следует отметить два особых случая:

- final, который мы видели ранее, предназначен для свойств только для чтения, копируется в резервное поле, но также не приводит к определению установщика.
- static копируется в резервное поле, но также приводит к тому, что методы доступа становятся статическими.
# Создание конструктора кортежей

 Аннотацию **@TupleConstructor -** groovy.transform.TupleConstructor

С помощью этой аннотации мы можем автоматически создать конструктор кортежей во время компиляции. Таким образом, конструктор можно найти в скомпилированном классе. Для каждого свойства в классе создается параметр в конструкторе со значением по умолчанию. Порядок свойств, определенных в классе, также определяет порядок параметров в конструкторе. Поскольку параметры имеют значения по умолчанию, мы можем использовать синтаксис Groovy и оставлять параметры в конце списка параметров, когда мы используем конструктор.

_**Student.groovy**_

```java
import groovy.transform.TupleConstructor

@TupleConstructor
class Student {
    String firstName
    Integer age
}
```

_**Test.groovy**_

```java
class Test {
    static void main(String[] args) {
        Student student1 = new Student(firstName: "Petro", age: 64)
        Student student2 = ["Evgeniy", 48] // благодаря аннотации @TupleConstructor
        println student2.age 
    } // main

} // class
```
