## Введение

Вы уже умеете использовать цикл `for` для перебора простых списков значений. Но в реальной жизни часто нужно работать с данными, которые хранятся не вручную, а в переменных или файлах. Например, список файлов в директории, список пользователей системы или данные из конфигурационного файла.

Этот урок поможет вам:

- Использовать цикл `for` с данными, хранящимися в переменной.
- Читать данные из файла и обрабатывать их в цикле.
- Избегать распространённых ошибок при работе с пробелами и специальными символами.
- Настроить поведение цикла с помощью переменной окружения `IFS`.

## Чтение данных из файла

Если данные хранятся в файле, вы можете прочитать их с помощью команды `cat` и передать в цикл `for`.

### Чтение списка городов из файла

Создайте файл `cities.txt`:

```no-highlight
Омск
Новосибирск
Тюмень 
Томск
Иркутск
```

Файл `read_cities.sh`:

```bash
#!/bin/bash
# Читаем список городов из файла

file="cities.txt"

for city in $(cat "$file")
do
    echo "Посетите красивый $city!"
done
```

![](https://ucarecdn.stepik.net/17fff098-f76a-468c-bb00-19dd6d9f057b/)

Команда `$(cat "$file")` читает содержимое файла и подставляет его как список значений для цикла `for`.

## Проблема с пробелами и решение через `IFS`

### Проблема: а что если в данных есть пробелы?

Допустим, у вас есть файл `cities.txt`:

```no-highlight
Нижний Новгород
Набережные Челны
Сергиев Посад
Вышний Волочёк
```

Обработка некорректным способом:

```bash
for city in $(cat cities.txt)
do
    echo "Посетите красивый $city!"
done
```

![](https://ucarecdn.stepik.net/303357ff-1bda-4f5a-987e-daeaa0ae5f1b/)

По умолчанию Bash использует пробел, табуляцию и перевод строки как разделители полей (`IFS`).

### Решение: изменить переменную `IFS`

Переменная `IFS` (Internal Field Separator) определяет, какие символы используются для разделения полей в данных. Чтобы цикл `for` воспринимал каждую строку как одно значение, нужно установить `IFS` равным только переводу строки.

**Исправленный скрипт:**

```bash
#!/bin/bash
# Читаем список городов из файла

file="cities.txt"

# Сохраняем старое значение IFS
IFS_OLD="$IFS"
# Устанавливаем IFS только на перевод строки
IFS=$'\n'

for city in $(cat "$file")
do
    echo "Посетите красивый $city!"
done

# Восстанавливаем старое значение IFS
IFS="$IFS_OLD"
```

![](https://ucarecdn.stepik.net/286ce833-ceb9-417f-859e-9e6a06e64873/)

Всегда сохраняйте старое значение `IFS`, если меняете его в скрипте — это хорошая практика для предотвращения ошибок в других частях кода.

## Другие варианты использования `IFS`

Вы можете настроить `IFS` под любой формат данных.

### Разделитель — двоеточие

Если данные в файле разделены двоеточием (например, как в `/etc/passwd`), установите `IFS=:`.

```bash
#!/bin/bash
# Парсим данные, разделённые двоеточием

file="users.txt"

IFS=:  # Устанавливаем разделитель

while read username password uid gid name home shell
do
    echo "Имя пользователя: $username"
    echo "Домашняя директория: $home"
    echo "---"
done < "$file"

# Восстанавливаем IFS (если нужно)
IFS=$' \t\n'
```

![](https://ucarecdn.stepik.net/e187b5ac-8b9d-44ee-aa10-329de6e6bb91/)

Здесь мы использовали `while read` вместо `for`, потому что `for` не очень удобен для парсинга строк с несколькими полями. Но `IFS` работает одинаково в обоих случаях.

## Практическое задание: создайте скрипт «Анализ логов»

### Цель:

Написать скрипт `analyze_logs.sh`, который:

1. Принимает имя файла логов как аргумент (`$1`).
2. Читает файл построчно.
3. Для каждой строки проверяет:
    - Если строка содержит слово "ERROR" — выводит её с пометкой `ОШИБКА`.
    - Если строка содержит слово "WARNING" — выводит её с пометкой `ПРЕДУПРЕЖДЕНИЕ`.
    - В остальных случаях — выводит строку без изменений.
4. В конце выводит общее количество строк, содержащих "ERROR" и "WARNING".

### Инструкция:

1. Создайте файл `analyze_logs.sh`.
2. Добавьте shebang `#!/bin/bash`.
3. Проверьте, что аргумент передан: `if [ $# -ne 1 ]; then ... exit 1; fi`.
4. Установите `IFS=$'\n'` для корректной работы с многострочными данными.
5. Используйте `for line in $(cat "$1")` для чтения строк.
6. Используйте `[[ "$line" == *ERROR* ]]` для проверки наличия подстроки.
7. Сохраните, дайте права: `chmod u+x analyze_logs.sh`.
8. Создайте тестовый файл `test.log` и запустите: `./analyze_logs.sh test.log`.

### Пример решения:

```bash
#!/bin/bash
# Анализ логов

if [ $# -ne 1 ]; then
    echo "Использование: $0 <имя_лог-файла>"
    exit 1
fi

logfile="$1"

# Сохраняем старое значение IFS
IFS_OLD="$IFS"
IFS=$'\n'

error_count=0
warning_count=0

for line in $(cat "$logfile")
do
    if [[ "$line" == *ERROR* ]]; then
        echo "ОШИБКА: $line"
        ((error_count++))
    elif [[ "$line" == *WARNING* ]]; then
        echo "ПРЕДУПРЕЖДЕНИЕ: $line"
        ((warning_count++))
    else
        echo "$line"
    fi
done

# Восстанавливаем IFS
IFS="$IFS_OLD"

echo ""
echo "=== Статистика ==="
echo "Ошибок: $error_count"
echo "Предупреждений: $warning_count"
```
