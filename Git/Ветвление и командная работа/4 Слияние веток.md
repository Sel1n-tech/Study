Команда **`git merge`** объединяет изменения из указанной ветки в текущую ветку, создавая коммит слияния если это необходимо.

## Рассмотренные сценарии

1. **Fast-forward merge** — быстрое (линейное) слияние. Не создает merge-коммит, если в главной ветке не было изменений.
    
2. **Опция --no-ff** — "no fast-forward". Принудительно создает merge-коммит, даже если в главной ветке не было изменений.
    
3. **Recursive merge** — поведение по умолчанию. Создается merge-коммит, только в случае, если главной ветке были изменения.
    
4. **Опция -m "Сообщение коммита"** — возможность указать сообщение для merge-коммита.
    

## Новые команды

```bash
# вызов краткой справки (в терминале) по команде git merge
git merge -h

# вывод списка коммитов 
# --oneline - для компактного вывода
# --graph - для графического отображения веток
# --all - для отображения всех веток
git log --oneline --graph --all

# создать новую ветку и сразу переключиться на нее
git switch -c feature/some_new_pages

# создать новые файлы (если их нет)
touch web_pages/page22.html
touch web_pages/page33.html

# откатить последний коммит, удаляя его из истории
git reset --hard HEAD~1

# слить ветку с принудительным созданием merge-коммита
git merge --no-ff feature/some_new_pages

# слить ветку с указанием сообщения для merge-коммита
git merge feature/auth_page -m "my custom merge commit..."

# забрать изменения из ветки master удалённого репозитория (origin)
git pull origin master
```
